Zephyrix

বিশ্বব্যাপী ব্যবহারের উপযোগী একটি নিরাপদ মেসেজিং ওয়েব অ্যাপ। ব্যাকএন্ড সম্পূর্ণ কাস্টম (AI দিয়ে লেখা, কোনো রেডিমেড BaaS নয়), Google লগইন নিজস্ব প্রবাহে, OTP ইমেইল পাঠায় আলাদা PHP সার্ভিস, এবং রিয়েল-টাইম মেসেজ, ফাইল ও ভয়েস মেসেজ ZEGOCLOUD দিয়ে।
তারিখ: ২২ নভেম্বর ২০২৬ প্ল্যাটফর্ম: ওয়েব (PWA) স্ট্যাটাস: বাস্তবায়নের জন্য প্রস্তুত

১মূল সিদ্ধান্ত (এই সংস্করণের ভিত্তি)

বিষয়সিদ্ধান্ত
ব্যাকএন্ড কোডসম্পূর্ণ AI দিয়ে তৈরি। Node.js + TypeScript, নিজস্ব API, নিজস্ব সেশন ও অথ লজিক।
রেডিমেড BaaSব্যবহার হবে না: Firebase, Supabase, Appwrite, Auth0, Clerk, Parse ইত্যাদি।
Google লগইননিজস্ব OAuth 2.0 Authorization Code + PKCE প্রবাহ। Google ID token যাচাইয়ে শুধু crypto লাইব্রেরি (jose) ব্যবহার, কোনো auth provider নয়।
OTP তৈরি ও যাচাইNode.js ব্যাকএন্ড। OTP শুধু hash হিসেবে ডাটাবেসে থাকবে।
OTP ইমেইল পাঠানোআলাদা PHP মেইল সার্ভিস। Node থেকে signed অনুরোধ যাবে, PHP SMTP-তে ইমেইল পাঠাবে।
রিয়েল-টাইম মেসেজ, ফাইল, ভয়েসZEGOCLOUD SDK। Server Secret শুধু Node ব্যাকএন্ডে।
ডাটাবেসPostgreSQL (মাইগ্রেশন দিয়ে), Redis (রেট লিমিট ও ক্যাশ)।
বাংলা ও ইংরেজিপ্রথম থেকেই সমর্থিত, পরে অন্য ভাষা যোগ করার কাঠামো।
কাজের ভাগ: আপনি ডেভেলপার হিসেবে সব কোড AI দিয়ে লেখাবেন, এবং নিজে কেবল সেটআপ করবেন (Google Cloud, ZEGO কনসোল, ডোমেইন, SMTP অ্যাকাউন্ট)। কোনো কোড হাতে লিখতে হবে না।

যাচাইয়ের ধাপ

  • state মেলানো (CSRF সুরক্ষা), state একবারের এবং ৫ মিনিটে মেয়াদোত্তীর্ণ
  • ID token-এর signature যাচাই Google-এর JWKS দিয়ে, iss, aud (আমাদের Client ID), exp, email_verified
  • sub দিয়ে ইউজার খোঁজা; না থাকলে নতুন ইউজার, থাকলে নাম ও ছবি আপডেট
  • নতুন সেশন তৈরি; প্রথম লগইনে ইউজারনেম সেট করতে বলা

৪ইমেইল OTP: তৈরি, পাঠানো ও যাচাই

উদ্দেশ্য

Google ছাড়াও ইমেইল দিয়ে লগইন বা নিশ্চিতকরণের জন্য নিজস্ব OTP ব্যবস্থা থাকবে। OTP ইমেইল পাঠানোর কাজ PHP সার্ভিস করবে, কারণ এটি আলাদা মেইল পরিকাঠামোতে চালানো সহজ।

নিয়মাবলি

বিষয়নিয়ম
OTP দৈর্ঘ্য ও মেয়াদ৬ সংখ্যা, ৫ মিনিট
সংরক্ষণশুধু HMAC-SHA256 hash (সার্ভার secret দিয়ে), প্লেইন টেক্সট নয়
একবার ব্যবহারসফল যাচাইয়ের পর বা নতুন OTP চাইলে আগেরটি বাতিল
ভুল চেষ্টাOTP-তে সর্বোচ্চ ৫ বার, তারপর ১৫ মিনিট লক
রেট লিমিটএকই ইমেইলে প্রতি ১ মিনিটে ১টি, দিনে সর্বোচ্চ ১০টি; একই IP-তে আলাদা সীমা (Redis)
তথ্য ফাঁস এড়ানোইমেইল আছে কিনা তা বোঝানো যাবে না; সবসময় একই বার্তা "যদি ইমেইল নিবন্ধিত থাকে, OTP পাঠানো হয়েছে"
মেইল ব্যর্থতাPHP থেকে ব্যর্থতা এলে Node retry করবে (২ বার, backoff), শেষে ব্যবহারকারীকে জানাবে

৫PHP মেইল সার্ভিস (OTP সেন্ডার)

দায়িত্ব

  • Node থেকে আসা signed অনুরোধ যাচাই করা
  • ইমেইলের টেমপ্লেট রেন্ডার করা (বাংলা ও ইংরেজি)
  • SMTP দিয়ে ইমেইল পাঠানো (PHPMailer বা Symfony Mailer)
  • পাঠানোর ফলাফল (সফল/ব্যর্থ, message ID) Node-কে ফেরত দেওয়া

নিরাপত্তা

অনুরোধ যাচাই

HMAC-SHA256 signature + timestamp (৫ মিনিটের বেশি পুরনো হলে প্রত্যাখ্যান) + nonce (replay রোধ)।

নেটওয়ার্ক

শুধু Node সার্ভারের IP থেকে অ্যাক্সেস (firewall), পাবলিক ইন্টারনেটে বন্ধ।

কনফিগারেশন

SMTP পাসওয়ার্ড ও signing secret environment variable-এ, কোডে নয়।

লগ

ইমেইল ঠিকানা মাস্ক করে লগ (যেমন a***@gmail.com), OTP কোড কখনো লগ নয়।

API চুক্তি (Node ↔ PHP)

POST /internal/send-otp
Headers:
  X-Timestamp: 1763812345
  X-Nonce: একবারের র্যান্ডম স্ট্রিং
  X-Signature: HMAC-SHA256(secret, timestamp + "." + nonce + "." + body)
Body (JSON):
  { "to": "user@example.com", "locale": "bn", "otp": "123456", "expires_minutes": 5 }

Response 200: { "status": "queued", "message_id": "..." }
Response 4xx/5xx: { "status": "error", "code": "..." }
OTP কোড PHP-তে যায়, তাই PHP সার্ভিসকে কঠোরভাবে সুরক্ষিত রাখতে হবে এবং তার লগে কখনো OTP লেখা যাবে না।

১০সেশন ও নিরাপত্তা

সেশন

Server-side, টোকেনের SHA-256 hash ডাটাবেসে। ৩০ দিন অ্যাবসোলিউট, ৭ দিন নিষ্ক্রিয়তা।

Cookie

HttpOnly, Secure, SameSite=Lax। লগইনে নতুন সেশন ID, পুরনোটি বাতিল।

রেট লিমিট

লগইন, OTP, মেসেজ পাঠানো ও সার্চে আলাদা সীমা (Redis)।

হেডার

HTTPS + HSTS, কঠোর CSP, X-Content-Type-Options, frame-ancestors none।

Secrets

Secret manager বা environment variable। কোডে বা Git-এ নয়।

নির্ভরতা
